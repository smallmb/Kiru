# 测试与验收规范
## 1. 基线与执行
在项目根目录使用当前已成功启动的 Flutter SDK；记录 flutter --version、flutter doctor -v、git rev-parse HEAD、git status --short。先记录已有分析/测试失败，再进行变更；禁止将已有失败伪装成通过。保留 pubspec.lock，不无故升级依赖。按任务执行 flutter analyze、相关 flutter test、必要的 flutter build windows / Android 构建和真机验证。测试不得依赖不稳定的未授权第三方资源，优先用 mock provider、本地 fixture 与合法测试流。
## 2. 核心验收矩阵
| ID | 场景 | 验收条件 |
|---|---|---|
| T01 | 启动、网络离线 | 本地可启动；外部服务故障独立降级 |
| T02 | 顶部分类 / 返回 | 保留筛选、滚动与页面状态，无重复导航 |
| T03 | 中文 / 英文 / 阿文 | 可切换、无缺失 key、无明显溢出；验证 RTL |
| T04 | 搜索与详情 | 同名影视、季集、动漫映射不串数据 |
| T05 | 多源并发 | 部分结果先显示；失败、超时不阻塞其他源 |
| T06 | 离页 / 快速选集 | 旧查询取消或失效，不污染新会话 |
| T07 | 源标签及排序 | 未知字段如实显示，声明和实际画质区分 |
| T08 | 断网 / 过期 URL | 重试有界，重新解析，手动切源可用 |
| T09 | 切源续播 | 同一内容进度恢复；不同集数不混用 |
| T10 | 1080p/4K 播放 | 实际分辨率与解码方式有证据，无持续异常 |
| T11 | 字幕 / 音轨 / 倍速 | 支持的平台正常切换、同步、进度调整 |
| T12 | Anime4K/FSR | 可开关并回退；原生与增强明确区分 |
| T13 | 退出/反复播放 | 释放播放器、订阅、计时器；无持续资源增长 |
| T14 | 收藏、历史、继续观看 | 重启后保留；删除与清空可确认 |
| T15 | 本地/NAS | 离线文件、权限错误、鉴权错误、断线恢复 |
| T16 | 隐私与安全 | 凭据不明文输出；未授权来源默认不启用 |
| T17 | 桌面/手机/TV | 键盘、触控、遥控器焦点和全屏退出正常 |
| T18 | 安装、升级、迁移 | 保留用户数据、更新渠道正确、可回滚 |
## 3. 播放器性能矩阵（每台设备单独记录）
| 测试素材 | 测试重点 |
|---|---|
| 1080p H.264 SDR | 首帧、拖动、稳定性 |
| 2160p HEVC Main10 SDR/HDR10 | 硬解、丢帧、色调映射及实际 HDR 输出 |
| 2160p AV1（兼容设备） | 解码方式及性能 |
| 1080p 动漫 + Anime4K/FSR | GPU 负载、帧率、关闭后恢复 |
| MKV 多音轨 + ASS/SRT | 音轨、字幕、同步 |
| HLS 合法测试流 | 缓冲、断线、清晰度切换 |
记录：OS、CPU/GPU、屏幕 HDR、内核及版本、媒体编码/分辨率/帧率、首帧耗时、丢帧/卡顿、CPU/GPU/内存、异常及回退。建议稳定网络下用至少 5 分钟固定样本比较；性能目标先建立基线再设阈值，不承诺全设备 4K 或 Dolby Vision。
