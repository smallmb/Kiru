# 开发约定（人工与 Codex）
## 1. 每次开发前
读取 README、PRD、架构、详细设计、路线图和对应验收规范。检查 git status 与现有改动，确认任务 ID 和影响范围；理解实际调用链，优先复用已有组件/服务。原版已由用户启动，不擅自重新安装 SDK、升级所有依赖、清理用户工作区或覆盖上游修改。
## 2. 目录与架构
先回答三个问题：业务职责归属哪里？哪些变化是外部依赖引起？调用方如何在不关心实现的情况下使用它？
外部适配隔离；内部业务聚合；不以层级数量评价架构。UI 不直接新增第三方网络抓取或持久化逻辑；共享能力仅在重复使用且边界稳定时提取。迁移旧模块前补行为测试；保持可回退，避免双实现。
## 3. 编码与 UI
遵循现有 Dart 风格、analysis_options、现有 theme/design tokens、路由与焦点机制；新增文案进入 ARB。不能硬编码颜色、尺寸、API 密钥或平台能力；避免无效重建、未取消的订阅、UI 线程重计算。保留顶部电影/剧集/动漫切换与源展示结构，交互修改需有明确依据。
## 4. 依赖与安全
新增依赖须记录必要性、维护情况、许可证、平台支持及替代方案；原生内核或 override 修改须先验证全部受影响平台。禁止在日志、文档、Git 中写入真实密钥。扩展与来源需权限及授权审查；不引入绕过 DRM 的逻辑。独立更新服务与品牌必须同时审计，分发遵守实际许可证。
## 5. 交付规则
每个任务产出：任务 ID、变更文件、实现说明、影响范围、测试结果、未解决问题、回滚方式。先测试后宣布完成；未验证事项明确标注。禁止为了测试通过删除既有断言或屏蔽错误。文档与代码同步，路线图仅在有证据时更新状态。
## 6. 给 Codex 的首轮任务指令
请读取 docs/product-development 下全部文档，以 DEVELOPMENT_ROADMAP.md 为任务来源。当前只执行 M0-01～M0-03：记录用户已运行版本的 SDK、Git、构建命令与依赖锁定情况；检查 Shell/Browse/WatchScreen/StreamService/PlayerScreen 的真实调用链；执行可行的基线分析及测试并记录已有问题。不得升级依赖、重构导航或播放内核、重命名应用、启用未经审核的来源、删除用户修改。输出基线记录至 docs/product-development/BASELINE_REPORT.md；完成后给出 M1-01 中文化与 M1-04 导航回归的具体文件改动建议。无法验证的项目标记待验证。
